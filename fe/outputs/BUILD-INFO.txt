本次改动: 局域网联机（房间发现 + 信令 + 对局同步），版本号升到 2.0

架构（三层，原生只做最笨的活）:
  Web 层 (app.js + net.js)        协议、会话、WebRTC、界面
  能力桥                           只有 4 个动作: announce / rooms / send / onBlob
  原生层                            UDP 广播发现 + UDP 单播透传

新增文件:
  www/net.js   传输层。原生桥 / 同源 HTTP 桥 / BroadcastChannel 三种实现，按可用性自动选择
               并逐级降级；不可用时联机入口自动隐藏，单机完全不受影响。

Windows 端 (Launcher.cs):
  - UDP 45455 广播房间：按每张网卡算出子网广播地址（并保留有限广播兜底），
    包体为 "YJA\t房间id\t房间名"，1.5 秒一次
  - 收到别人的广播就登记房间（6 秒未刷新即过期）；收到 "YJS\t<json>" 数据包就投递给页面
  - 页面通过同源端点使用（无需 CORS）：
      GET  /lan/hello      能力探测（版本、UDP 端口、服务是否启用）
      POST /lan/announce   开始/停止广播房间
      GET  /lan/rooms      当前发现的房间列表
      POST /lan/send       把一段不透明数据发给某台设备
      GET  /lan/inbox      长轮询取回收到的数据
  - 原生层完全不解析信令内容，WebRTC 协商全部在页面里完成
  - HTTP 请求解析升级为支持 POST 与 Content-Length 请求体（原来只支持 GET）

Web 端:
  - 侧栏新增“联机”页：创建房间（房间名 / 我方执棋 红·黑·随机）、局域网房间列表、
    手动地址加入、连接状态与对手信息、认输 / 重开 / 离开，以及房间日志
  - 顶栏状态区新增联机徽标：等待对手 / 执红·执黑 / 延迟
  - 聊天在联机时改为真实收发，离线仍然是本地模拟
  - 协议 v1：hello / welcome / move / chat / undoReq·undoOk·undoNo / resign /
    newGame / syncReq / sync / ping / pong。状态类消息都带 ply，对不上就请求全量快照对齐
  - 悔棋改为双方确认后才生效；认输与重开由发起方广播
  - 无联机层时入口自动隐藏，单机流程一行未改

降级顺序: 原生桥 -> 同源 HTTP /lan/* -> BroadcastChannel（同机多窗口，开发与验收用）-> 隐藏
