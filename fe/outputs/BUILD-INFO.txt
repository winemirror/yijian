本次改动: TURN 中继打通（服务端 + 客户端 + 部署）

背景：3.0/3.1 只下发 STUN，两端都在运营商 CGNAT 后面（例如都用手机流量）时
无法直连，对局建不起来。coturn 其实早已在服务器上跑着并配好了 use-auth-secret，
缺的是信令服务端不下发 TURN。

服务端（fe/work/server/server.mjs）:
  - iceServers() 现在同时下发 STUN 与 TURN：
    username = "<过期unix时间戳>:<随机串>"，
    credential = base64(HMAC-SHA1(static-auth-secret, username))，即 coturn 的 REST 临时凭证。
    凭证即时计算、只在内存里，静态密码从不下发也不落库。
  - TURN_URL 支持逗号分隔多条，一条时保持字符串、多条时给 urls 数组；
    部署里下发 udp + tcp 两条（UDP 快，UDP 被封时 TCP 兜底）。
  - TURN_TTL 夹在 60 ~ 86400 秒之间，避免配错成 0 或过大。
  - /health 新增 stun / turn 计数；启动日志打印 stun/turn/ttl。

客户端（fe/work/www/net.js + app.js）:
  - 服务端下发的 ICE 列表原本就会被原样交给 RTCPeerConnection，本次补上可观测性：
    拿到 typ relay 候选时在房间日志里提示「已获得中继候选（TURN 中继可用）」。
  - 新增 Net.turnCheck()：用 iceTransportPolicy "relay" 起一条临时连接只收集中继候选，
    能拿到 relay 候选即代表凭证与 coturn 都通；未配置 TURN 时直接返回 no-turn-configured。
  - 「网络自检」按钮在服务器可达性之后追加一次中继自检并写进房间日志。
  - status() 新增 turn 字段（TURN 条目数）。
  - 静态资源版本号统一升到 3.2.0-20261016，避免旧缓存。

部署（fe/work/server/deploy.sh + coturn.conf）:
  - deploy.sh 新增 PUBLIC_IP / TURN_SECRET / TURN_TTL / REALM / TURN_URL 支持，
    未显式给 TURN_URL 时按 PUBLIC_IP 自动生成 udp+tcp 两条；
    INSTALL_COTURN=1 时渲染 /etc/turnserver.conf（先备份）、重启 coturn。
  - coturn.conf 改为可渲染模板（__PUBLIC_IP__ / __TURN_SECRET__ / __REALM__）。

验证:
  verify-server 新增：TURN 凭证等于 base64(HMAC-SHA1(secret, username))、默认 600 秒有效期、
    多 URL 合并成 urls 数组、TURN_TTL 生效、只给 URL 不给 secret 时不下发、/health 的 stun/turn 计数。
  verify-net 新增：未配置 TURN 时返回 no-turn-configured、拿到 relay 候选时自检通过、
    status().turn 计数正确、STUN 条目不被算成 TURN。
  六个套件全绿；perft(4) = 3290240。

已知限制（3.2）:
  - 中继流量跑在这台 VPS 上，带宽与延迟都不如直连；并发路数受 min-port/max-port 限制，
    人多时需要扩端口段或多加一台 TURN。
  - 客户端页面是安全上下文，服务端仍必须用 wss://（客户端不解析信令内容，
    TURN 也是服务端下发，客户端零配置）。
  - 服务端不存棋局，重启会让在线房间失效（客户端重连重建即可）。
