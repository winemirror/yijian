本次改动: 修复加入房间时报「通道错误：Cannot read properties of undefined」

根因:
  scan() 返回的房间是扁平结构 {id, name, ip, port}（安卓插件和桌面的 /lan/rooms 都
  是这个形状），但 joinRoom() 读的是 target.addr。于是 state.transport.send(undefined, ...)
  抛出 TypeError，被 catch 兜住后就显示成那句「通道错误」。
  这个 bug 桌面端同样存在，只是先在安卓上被碰到。
  之前的测试没抓到，是因为测试里用的 BroadcastChannel 传输恰好自己构造了 addr 字段。

修复:
  - net.js 新增 normalizeRooms()：不论传输层给的是 addr 还是扁平的 ip/port，
    scan() 一律返回带 addr 的房间对象（同时保留 ip/port 方便界面显示）。
  - 顺手加固了几处:
      * 错误信息改成描述式（名称 + 消息 + 首个栈帧），不再只剩半句 message
      * offer / answer 缺少 sdp 时给出明确提示，而不是继续走进 WebRTC 里崩
      * Capacitor 插件先调一次 status() 探活再采信（Capacitor 的插件代理
        即使原生侧缺失也会存在，只看代理会有误判）
      * 连接断开回退时按 host / guest 给出正确阶段
      * app.js 的搜索房间 / 创建房间 / 加入房间都加了 try-catch，
        失败写进「房间日志」而不是变成未捕获的异常

回归测试:
  verify-net 新增一条：原生桥返回“扁平房间”时，scan() 之后必须带 addr，
  且 joinRoom 必须把 offer 发到 10.0.0.9:45455。修复前这条是红的。
