本次改动: 新增观战功能（第三者加入不影响对局）

背景:
  原来 net.js 是严格 1 对 1（一个 RTCPeerConnection、一个 DataChannel、一个 state.peer），
  观战者只能连到房主（房间广播方），所以必须让房主同时维持多条连接。

实现:
  - net.js 改为多对端：peers 以对端地址为键，房主为每个进来的 offer 建一条独立连接；
    send() 默认广播给所有已连对端，sendTo(id, msg) 定向发送；setPeerKind 标记身份。
  - 协议加意图：hello { want: "play" | "spectate" }。
      玩家 -> welcome { side, name }（与之前一致）
      观众 -> welcome { role:"spectator", snapshot, elapsedMs, turnMs, redName, blackName }
      对局席已满时再来玩家 -> welcome { full:true }，客户端提示改用观战
  - 观众端：mySide / peerSide 均为 null，canPlayNow() 与 canMoveLocally() 恒为 false
    （点不动棋盘），隐藏「认输 / 重开」，状态显示「观战中（不执棋）」；
    收到 welcome 时用 snapshot 对齐当前局面与棋谱，时钟按 elapsedMs / turnMs 校准。
  - 房主把走子 / 聊天 / 重开 / 认输 / 对齐等事件广播给所有对端；观众只收不发。
  - 房间列表每行改成两个按钮：加入 / 观战。
  - 房主状态里显示观众人数；日志记录「xxx 加入观战（共 N 人观战）」「观众已连上」「一名观众离开了」。

验证:
  verify-net 新增两组用例：
    * 房主同时接受两名加入者，各自建连接、各自收到应答；
      广播能同时到达两人；sendTo 只发给指定对端；setPeerKind 区分棋手/观众计数。
    * 观众无座位、不能走子、能收到running快照（history=1）、时钟按主机校准。
  5 个套件全绿；perft(3) = 79666
