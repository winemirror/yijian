本次改动: 修复"手机加入房间时报 server timeout: room.joined"

现象（实测复现）：
  手机用流量、电脑用宽带，电脑建房拿到房间码 FPATHY；手机点加入后
  8 秒整报 `通道错误：Error: server timeout: room.joined`。

定位：
  服务端日志显示手机确实连上过（14:45:36），房间也建好了（14:45:43），
  但**没有任何 room.join 记录**，而连接直到 14:46:26 才断——也就是说
  客户端那条 room.join 根本没发出去，服务端当然不会回包。
  根因在客户端：信令 socket 已经死了（iOS 把网页切到后台会掐掉 WebSocket，
  更隐蔽的是"半开连接"：本地 readyState 还是 open，报文却石沉大海），
  而 post() 发不出去时只是静默返回 false，调用方只能干等满 8 秒超时。

客户端（fe/work/www/net.js + app.js）:
  - waitFor 的等待项现在带 reject；socket 触发 onclose 时统一 failWaiters，
    立刻以 signalling-closed 失败，不再干等超时。
  - onclose 里清空 readyPromise / infoPromise / socket，使下一次 connect()
    能真正重开一条连接（之前 readyPromise 永远指向死连接，重连永远不会发生）。
  - 发送失败不再静默：postOrThrow() 在 room.create / room.list / room.join
    发不出去时立刻抛 signalling-not-ready。
  - joinSignalling 在真正 join 之前先发一条应用层 ping 并等 2.5 秒 pong，
    专门用来戳穿"半开连接"。
  - joinByCode 遇到上述传输层错误会自动重连并重试一次（用户无感）。
  - 错误文案翻译成人话：signalling-closed/signalling-not-ready → "信令连接已断开
    （页面切后台后常见），请重试"；server timeout → "服务器无响应，请检查网络后重试"；
    另外补上 no_room / room_full / already_in_room 的中文提示。
  - 房间日志新增两类事件：信令连接已断开、正在重连后重试…。

服务端（fe/work/server/server.mjs）:
  - sendError() 增加日志（error <code> -> <clientId>）。
  - room.join 在处理前先记一行 room.join <CODE> <- <clientId>。
    以前只有成功的 join 会写日志，出问题时从服务端看不出"客户端到底有没有发过来"。
